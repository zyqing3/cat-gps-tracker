# 固件架构设计：GPS 项圈（T-SIM7670G-S3）

> 面向读者：初中生。这是"开工写代码之前的蓝图"，先讲清楚程序长什么样、怎么运转。
> 依据：路线图已定决策（Arduino C++ / Arduino CLI / Traccar demo / 每分钟上报一次 / USB 供电）与三份调研报告。

---

## 1. 目标与约束

- 目标：每分钟把 GPS 定位信息上传到 Traccar demo 服务器，服务器上能在地图看到实时位置。
- 已定决策（详见路线图 #1）：
  - 语言/环境：**Arduino C++，Arduino CLI**
  - 硬件：LilyGO T-SIM7670G-S3（ESP32-S3 + SIM7670G 内置 GPS）
  - 上传：HTTP(S) POST → Traccar（OsmAnd 协议，端口 5055），**每 60 秒一次**
  - 供电：USB/充电宝，**第一阶段不考虑低功耗**：4G 保持连接、GPS 保持供电，全程不进入休眠（省电策略留给第二阶段电池版）
- 不在范围：手机 App、电池低功耗、外壳。

## 2. 总览：一个主程序 + 一个参数文件

demo 阶段保持简单，**所有可改的东西集中在一个文件**，主程序一个文件：

```
firmware/
├── gps_collar.ino      ← 主程序（启动、循环、状态机，函数都在这里）
└── config.h            ← 参数文件（deviceid、服务器地址、上报间隔、APN……改这里就行）
```

> 为什么不用复杂的多文件结构？因为固件主体直接基于 LilyGo 官方 Traccar 示例（507 行、SIM7670G 实测过），demo 阶段改参数 + 微调逻辑就够。将来功能多了（比如第二阶段省电、App 联动）再拆成多模块。

## 3. 启动流程（上电后依次发生什么）

```
┌─────────────┐   ┌──────────────┐   ┌────────────┐   ┌──────────┐   ┌─────────────────┐
│ 1. 串口初始化 │ → │ 2. 模块开机   │ → │ 3. 联网    │ → │ 4. 开 GPS │ → │ 5. 进入主循环    │
│ USB 监视 115200│   │ PWRKEY=18 脉冲 │   │ SIM/GPRS   │   │ 给天线供电  │   │ 每 60 秒：定位→上传│
│ Serial1 115200 │   │ 等 AT 就绪    │   │ 等网络注册  │   │ 等首次定位  │   │  → 等待 → 重复    │
└─────────────┘   └──────────────┘   └────────────┘   └──────────┘   └─────────────────┘
```

每一步的要点（对应调研结论）：

1. **串口初始化**：USB 串口看日志；`Serial1`（RX=10 / TX=11 / 115200）连接 4G 模块。
2. **模块开机**：用 `PWRKEY=18` 给一个脉冲唤醒 SIM7670G，然后等它回 `AT` 就绪。
3. **联网**：检查 SIM 卡 → 等待注册到运营商网络 → `gprsConnect(APN)`。普通 SIM 卡 APN 一般留空或按运营商填（config.h 里可改）。
4. **开 GPS**：调 `modem.enableGPS(4, 1)`（库内部会发 `AT+CGDRT=4,1` 和 `AT+CGSETV=4,1` 给**有源天线供电**——漏掉这一步永远搜不到星）；等待首次定位，**室外开阔处约 30 秒到几分钟**。
5. **进入主循环**（见下节）。

## 4. 主循环状态机

```
            每 60 秒执行一次
                  │
                  ▼
        ┌─────────────────┐
        │  读取 GPS 位置    │
        │ getGPS(lat,lon)  │
        └────────┬────────┘
                 │
        有定位吗？─────没有────▶ 打印"搜星中，跳过本次" ──┐
                 │                                    │
                有                                   │
                 ▼                                    │
        ┌─────────────────┐                          │
        │ 组装 OsmAnd 数据  │                          │
        │ deviceid+经纬度…  │                          │
        └────────┬────────┘                          │
                 ▼                                    │
        ┌─────────────────┐                          │
        │ HTTPS POST 上传  │                          │
        │ 失败→重试 1 次    │                          │
        └────────┬────────┘                          │
                 │                                    │
        ┌────────┴────────┐                          │
        │ 检查网络还通吗？   │                          │
        │ 断了→重连 GPRS    │                          │
        └────────┬────────┘                          │
                 │◄───────────────────────────────────┘
                 ▼
         等待到下一个 60 秒周期（简单 delay；4G 不断网、GPS 不断电，不进入休眠）
```

**为什么让 4G 和 GPS 常开？**（第一阶段刻意求简单）

- 4G 保持连接：不用每次上报前重连，省掉断线重连的复杂逻辑
- GPS 保持供电：模块不关机时每次定位只需几秒（官方实测），不用反复冷启动
- 代价是费电，但第一阶段用 USB/充电宝供电，不在意；第二阶段做电池版时再加省电策略

## 5. 功能函数清单

| 函数 | 干什么 |
|---|---|
| `setup()` | 按第 3 节的 1→4 步初始化 |
| `loop()` | 按第 4 节状态机循环 |
| `modemPowerOn()` | PWRKEY 脉冲开机 + 等 AT 就绪 |
| `connectNetwork()` | 等 SIM 注册 + GPRS 连接，失败自动重试（最多 N 次） |
| `startGps()` | `enableGPS(4,1)` + 等首次定位（带超时） |
| `readGps()` | `getGPS()` 读经纬度/时间/速度；解析失败返回 false |
| `uploadLocation()` | 组装 OsmAnd 查询串 → HTTPS POST → 检查返回码，失败重试 1 次 |
| `checkAndReconnect()` | 每个周期末尾查网络状态，断了重连 |

> 注意：刻意**没有**电源管理（睡眠/唤醒）函数——第一阶段 4G 和 GPS 常开；第二阶段做电池版时再加。

## 6. 错误处理策略（demo 阶段"能跑、不崩溃、有日志"）

| 情况 | 策略 |
|---|---|
| 上电后模块没响应 | 重发 AT 若干次，还不行就重启模块（PWRKEY 再脉冲） |
| 搜不到星（室内/冷启动） | 不阻塞：超时就跳过本次上报，打印"搜星中"；拿到首次定位后后续很快 |
| 上传失败 | 重试 1 次；仍失败则打印错误码，等下个周期再试（不囤数据，demo 不需要） |
| 网络断了 | 检测到注册状态丢失 → 重新 GPRS 连接 |
| 所有错误 | 统一走串口日志：`[时间] 发生了什么`，方便插电脑看 |

## 7. config.h 参数表（改这里，不改主程序）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `TRACCAR_SERVER` | `demo.traccar.org` | 服务器地址（将来自建就改这里） |
| `TRACCAR_PORT` | `5055` | Traccar 上报端口 |
| `DEVICE_ID` | `123456789` | Traccar 设备 ID（注册账号后拿到，必改） |
| `REPORT_INTERVAL_S` | `60` | 上报间隔（秒） |
| `APN` | `""` | 运营商接入点，普通卡一般留空 |
| `GPS_TIMEOUT_S` | `120` | 等首次定位的最长时间 |

## 8. 与调研结论的对应（防踩坑清单）

1. **必须用 LilyGo 分支版 TinyGSM**（原版编译不过）——Arduino CLI 用 `--libraries` 直接引用仓库 `lib/`。
2. **开 GPS 前给有源天线供电**（库内已实现，别删那两行）。
3. **必须接有源 GPS 天线**，室内基本收不到；演示拿到室外。
4. 官方 wiki 引脚写错了（RX=4/TX=5 是另一块板），以 `utilities.h` 为准：RX=10/TX=11/PWRKEY=18。
5. GPS 返回时间是 UTC，显示北京时间要 +8 小时。
6. USB 供电要能供 2A。
